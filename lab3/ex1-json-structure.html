Exercise 1: Explore and Understand JSON Structure

A breakdown of how an Open Library book record is organized, with real examples pulled from the file.

Source

I studied the Open Library edition record for Fantastic Mr. Fox by Roald Dahl (openlibrary.org/books/OL7353617M.json) in a JSON formatter before writing any code.

Overall Organization

The whole file is one JSON object wrapped in curly braces. That object represents one edition of one book, and every piece of information about it sits in a key at the top level. Some keys hold a single value, some hold lists, and a few hold small objects of their own. Nothing goes deeper than about three levels, so the record is wide rather than deep.

Main structure
One top level object describing a single book edition
Main keys
title, authors, publishers, publish_date, number_of_pages, isbn_10, isbn_13, covers, first_sentence, works, key
Simple values
Text: title, publish_date, key, ocaid. Numbers: number_of_pages, revision, latest_revision
Collections (arrays)
publishers, isbn_10, isbn_13, covers, contributions, source_records, local_id, authors, languages, works
Structured values (objects)
first_sentence, created, last_modified, type, identifiers, classifications
Nesting
Yes. authors is an array of objects, and identifiers is an object whose values are arrays.

Name/Value Pair

A key in quotes, a colon, and a value. This one holds a plain number.

"number_of_pages": 96

Object

Curly braces holding name/value pairs. Open Library wraps the first sentence in an object that also records its type.

"first_sentence": {
  "type": "/type/text",
  "value": "Down in the valley there were three farms."
}

Array

Square brackets holding an ordered list. Even single values like the ISBN are stored this way so the field can hold more later.

"covers": [15152634, 8739161, -1]
"isbn_13": ["9780140328721"]

Nested Structure

Structures inside structures. authors is an array of objects, and identifiers is an object whose values are arrays.

"authors": [
  { "key": "/authors/OL34184A" }
],
"identifiers": {
  "goodreads": ["1507552"],
  "librarything": ["6446"]
}

What Stood Out

The author's name isn't in the record at all. authors only holds a key that points to a separate author record, so showing "Roald Dahl" takes a second lookup. A lot of single values also come wrapped in arrays or small objects, so any code reading this file has to check the shape of each field before using it.

Exercise 1: JavaScript and jQuery Comparison

The six instructor examples, each rewritten in jQuery and compared with the instructor's jQuery version.

How I Did This

For each of the six instructor examples, I ran the JavaScript version first, rewrote it in jQuery on my own, then opened the instructor's jQuery version to compare. Each section below shows the original JavaScript, my jQuery rewrite running live, and what I noticed when I compared mine to the instructor's.

1. Calculations and Output

Original JavaScript

var x = 10;
var y = 4.5;
var result1 = x + y;
document.getElementById("result").innerHTML = "<p>x=" + x + ", y=" + y + "</p>";
document.write("<p>x + y = " + result1 + "</p>");
document.write("<p>x - y = " + (x - y) + "</p>");
document.write("<p>x * y = " + x * y + "</p>");
document.write("<p>x / y = " + x / y + "</p>");

Run the instructor's JavaScript version

My jQuery Rewrite

$(function () {
  var x = 10;
  var y = 4.5;
  $("#calc-out").html("<p>x=" + x + ", y=" + y + "</p>");
  $("#calc-out").append("<p>x + y = " + (x + y) + "</p>");
  $("#calc-out").append("<p>x - y = " + (x - y) + "</p>");
  $("#calc-out").append("<p>x * y = " + (x * y) + "</p>");
  $("#calc-out").append("<p>x / y = " + (x / y) + "</p>");
});

Running live:

Compared with the Instructor's jQuery Version

My version matched the instructor's approach: .html() for the first line, then .append() for each result. The instructor's jQuery version stops after subtraction and leaves multiplication and division as commented-out document.write() lines with the question "will these work?" They won't. document.write() after the page loads wipes the whole page, so I finished all four operations with .append().

2. Loops

Original JavaScript

var level = 5;
document.write("<ul>");
for (i = 0; i < level; i++) {
  document.write("<li>List item " + i + "</li>");
}
document.write("</ul>");

Run the instructor's JavaScript version

My jQuery Rewrite

$(function () {
  var level = 5;
  var items = "";
  for (var i = 0; i < level; i++) {
    items += "<li>List item " + i + "</li>";
  }
  $("#loop-out").html("<ul>" + items + "</ul>");
});

Running live:

Compared with the Instructor's jQuery Version

The instructor's version calls .append("<ul>"), then appends each <li>, then appends "</ul>". That looks right but isn't. jQuery builds a complete element from every string, so the first call creates an empty <ul></ul> and the list items land outside it. I built the whole list as one string first and inserted it once, which keeps the items inside the list and touches the DOM one time instead of seven.

3. Functions

Original JavaScript

function createList() {
  var level = 5;
  document.write("<ul>");
  for (i = 1; i <= level; i++) {
    document.write("<li>" + i + "</li>");
  }
  document.write("</ul>");
}
function createList2(level, type) {
  document.write("<" + type + ">");
  for (i = 1; i <= level; i++) {
    document.write("<li>" + i + "</li>");
  }
  document.write("</" + type + ">");
}
createList();
createList2(10, 'ol');

Run the instructor's JavaScript version

My jQuery Rewrite

function createList(level, type) {
  var $list = $("<" + type + ">");
  for (var i = 1; i <= level; i++) {
    $list.append($("<li>").text(i));
  }
  return $list;
}

$(function () {
  $("#func-out").append(createList(5, "ul"));
  $("#func-out").append(createList(10, "ol"));
});

Running live:

Compared with the Instructor's jQuery Version

The JavaScript example needed two functions because one had the list size hardcoded. I folded them into one function with parameters, like createList2, and had it return a jQuery element instead of writing to the page. That makes it reusable: the caller decides where the list goes. The instructor's jQuery version has the same <ul> append issue from the loop example.

4. DOM Access

Original JavaScript

document.write("The link's innerText: " +
  document.getElementById("w3clink").innerText);
document.write("The link's innerHTML: " +
  document.getElementById("w3clink").innerHTML);
document.write("The link's href: " +
  document.getElementById("w3clink").attributes[1].nodeValue);
document.write("The img's src: " +
  document.getElementById("w3cimg").attributes[1].nodeValue);

Run the instructor's JavaScript version

My jQuery Rewrite

$(function () {
  var $out = $("#dom-out");
  $out.append("<b>The link's inner text:</b> " + $.trim($("#w3clink").text()));
  $out.append("<br><b>The link's inner HTML:</b> ");
  $out.append($("<code>").text($.trim($("#w3clink").html())));
  $out.append("<br><b>The link's href:</b> " + $("#w3clink").attr("href"));
  $out.append("<br><b>The image's src:</b> " + $("#w3cimg").attr("src"));
});

Running live:

W3C

Compared with the Instructor's jQuery Version

The JavaScript version reads attributes by position with attributes[1], which breaks if anyone reorders the attributes in the HTML. jQuery's .attr("href") asks for the attribute by name, so it always gets the right one. My version matches the instructor's. The one change I made was showing the inner HTML as escaped text, since inserting it directly would render a second copy of the link instead of showing its markup.

5. Click Events

Original JavaScript

function displayGrade() {
  var score = document.getElementById('score').value;
  var grade;
  if (score >= 90) grade = 'A';
  else if (score >= 80) grade = 'B';
  else if (score >= 70) grade = 'C';
  else grade = 'F';
  document.getElementById("result").innerHTML =
    "Your score is " + score + " and your grade is " + grade;
}
// <input type="button" onclick="displayGrade()">

Run the instructor's JavaScript version

My jQuery Rewrite

function displayGrade() {
  var score = $("#score").val();
  var grade;
  if (score >= 90) grade = "A";
  else if (score >= 80) grade = "B";
  else if (score >= 70) grade = "C";
  else grade = "F";
  $("#grade-out").html("Your score is " + score + " and your grade is " + grade);
}

$(function () {
  $("#calculate").on("click", displayGrade);
});

Running live:

Compared with the Instructor's jQuery Version

The big difference is where the event is attached. The JavaScript version puts onclick="displayGrade()" right in the HTML. jQuery keeps the HTML clean and attaches the handler in the script with .on("click", displayGrade). The instructor's version wraps it in an extra anonymous function and mentions passing the function directly as an option, which is what I did. The grading logic itself didn't change at all.

6. CSS Manipulation

Original JavaScript

function changeColor() {
  document.getElementById("result").style.backgroundColor = getRandomColorCode();
}
function changeSize() {
  var h = Math.floor(Math.random() * 100) + 50;
  var w = Math.floor(Math.random() * 200) + 200;
  document.getElementById("result").style.height = h + "px";
  document.getElementById("result").style.width = w + "px";
}
function changeBorder() {
  var w = Math.floor(Math.random() * 20) + 5;
  document.getElementById("result").style.borderWidth = w + "px";
  document.getElementById("result").style.borderColor = getRandomColorCode();
}
// buttons use onclick="changeColor()" and so on

Run the instructor's JavaScript version

My jQuery Rewrite

function getRandomColorCode() {
  var r = Math.floor(Math.random() * 256);
  var g = Math.floor(Math.random() * 256);
  var b = Math.floor(Math.random() * 256);
  return "rgb(" + r + "," + g + "," + b + ")";
}
function changeColor() {
  $("#welcome").css("background-color", getRandomColorCode());
}
function changeSize() {
  $("#welcome").css({
    height: Math.floor(Math.random() * 100) + 50 + "px",
    width: Math.floor(Math.random() * 200) + 200 + "px"
  });
}
function changeBorder() {
  $("#welcome").css({
    borderWidth: Math.floor(Math.random() * 20) + 5 + "px",
    borderColor: getRandomColorCode()
  });
}
function changeStyle() { changeColor(); changeSize(); changeBorder(); }

$(function () {
  $("#change1").on("click", changeStyle);
  $("#change2").on("click", changeColor);
  $("#change3").on("click", changeSize);
  $("#change4").on("click", changeBorder);
});

Running live:

Welcome

Compared with the Instructor's jQuery Version

In the instructor's jQuery version, changeBorder() still uses document.getElementById(...).style, so it was never fully converted. I rewrote it with .css() like the others and used the object form to set two properties in one call. I also changed Math.random() * 255 to * 256, because Math.floor of * 255 can never actually reach 255.

Overall Differences

Element selection
document.getElementById("result") becomes $("#result"). jQuery uses CSS selector syntax, so the same function works for IDs, classes, and tags.
DOM manipulation
.text(), .html(), and .attr() work as both getters and setters, and they can be chained.
Event handling
JavaScript examples used inline onclick attributes. jQuery attaches handlers in the script with .on("click"), keeping HTML and behavior separate.
Output generation
The JavaScript examples lean on document.write(), which only works while the page is loading. jQuery's .html() and .append() work any time.
CSS manipulation
One .css({ ... }) call replaces several element.style.property lines.
Code length
The jQuery versions were shorter every time, mostly because they don't repeat document.getElementById. The core logic (math, loops, if statements) stayed the same.

Exercise 2: jQuery ready() and Event Handling

Two paragraphs, two buttons, and a look at why $(document).ready() matters.

Working Demo (Part B)

Paragraph 1: The first button hides only this paragraph.

Paragraph 2: The second button hides only this paragraph.

Part A: One Handler for Both Buttons

My first version attached the same click event to both buttons, so clicking either one hid both paragraphs.

$(document).ready(function () {
  $("#btn1, #btn2").click(function () {
    $("#p1, #p2").hide();
  });
});

Part B: Control Individual Elements

Giving each button its own handler and its own target lets them work separately. This is the version running in the demo above.

$(document).ready(function () {
  $("#btn1").click(function () { $("#p1").hide(); });
  $("#btn2").click(function () { $("#p2").hide(); });
});

Part C: What Happens Without $(document).ready()

Does the page still work? Only if the script comes after the buttons. When I removed the wrapper and left the script in the <head>, nothing happened on click. The script ran before the buttons existed, so $("#btn1") matched nothing and no handler was attached. No error shows up either, which makes it easy to miss.

Does script location matter? Yes. Moving the same unwrapped script to the bottom of the <body> made it work again, because by then the browser had already built the buttons.

Why is ready() useful? It waits until the DOM is fully built, so the code works no matter where the script tag sits. I restored the wrapper for the published version.

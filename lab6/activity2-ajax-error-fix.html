Activity 2: AJAX Error Investigation

Why the page refreshed instead of running AJAX, and how event.preventDefault() fixes it.

Fixed Version

Both controls now load results from the Google Books API with AJAX. The page stays put and the counter below doesn't reset.

Load content in AJAX way here

What I Found in Developer Tools

Two default behaviors were taking over. With the Network tab open and "Preserve log" checked, a real refresh shows up as a new document request for the page, and the Console clears. A working AJAX call shows up as an xhr/fetch request to googleapis.com instead. In the original file, clicking the link added # to the address bar and jumped to the top of the page rather than staying put, and the button's request returned raw JSON text.

The link
<a href="#"> follows its href when clicked. With # it jumps to the top and adds a history entry. With any real URL (my fixed version points the link back at this same page on purpose) it loads a whole new page, wiping out whatever AJAX just inserted.
The form
A form's default action is to submit, which reloads the page. Any <button> inside a form is a submit button unless it says otherwise, and pressing Enter in a form submits it too. In the original file the button happens to be <input type="button">, which doesn't submit by itself, but swapping it for a normal <button> (as most people would) triggers a full reload.
Wrong method
.load() is meant for HTML. The Google Books API returns JSON, so even when the request worked, the original dumped raw JSON text into the div.

The Fix

Original script

$(document).ready(function ()
    {
        $("#button1").click(function ()
        {
            $("#ajaxDiv1").load("https://www.googleapis.com/books/v1/volumes?q=php%20mysql").hide().fadeIn("slow");
        });
		
		$("#button2").click(function ()
        {
            $("#ajaxDiv1").load("https://www.googleapis.com/books/v1/volumes?q=php%20mysql").hide().fadeIn("slow");
        });
    });

Run the original file

Fixed event handlers

$(document).ready(function () {
  // 1. The button sits inside a form. Stop the form's default submit.
  $("#bookForm").on("submit", function (event) {
    event.preventDefault();
    loadBooks();
  });

  // 2. The link's default action is to navigate to its href. Stop that too.
  $("#button2").on("click", function (event) {
    event.preventDefault();
    loadBooks();
  });
});

The form is handled through its submit event rather than the button's click, so the Enter key is covered too. loadBooks() uses $.getJSON() and builds a readable list instead of dumping raw JSON.

Questions to Consider

1. Why does the page refresh? The browser runs each element's built-in action after the click handler finishes. The AJAX request starts, but the navigation or form submission immediately replaces the page, so the response has nowhere to go.

2. What is the default behavior of these elements? A link navigates to the URL in its href. A form submits to its action URL, or to the current page when there isn't one, which reloads it.

3. How does event.preventDefault() help? It tells the browser to skip the element's built-in action for that one event. The click or submit still runs my handler, but no navigation happens, so the AJAX response can update the div and the rest of the page stays exactly as it was.
